> 来源：goFinder Issue #7 独立 T3 Code Worktree 需求研究会话，2026-11-13。
> 需求：[Issue #7：对用户的快捷键操作给到一个视觉反馈](https://github.com/aoyamashou/goFinder/issues/7)；父代理已回复「已受理」，本会话不再留言。
> 研究基线：`origin/main` = `40645889e5a5a53f02ddd2900f2ce718f2ecf715`（含 Issue #6 的 PR #12）；功能分支 `t3/shortcut-feedback-prd`，从原准备提交 `0d9a086` 快进到该基线。
> **状态：可以执行（Claude 审查，2026-11-13，基于 5c67f4b）。** 以文末「Claude 审查记录」为准，它简化了第 3–6 节的方案，冲突处以审查记录为准。实现后仍须 Claude 代码审查；PR、合并、回复和关闭 issue 照旧，发版另需用户指示。

## 要改什么、为什么

为复制、复制路径、剪切待粘贴、回到起点、隐藏文件切换，以及真正改变排序的操作提供短暂、底部居中的文字反馈。用户不必低头寻找状态栏，即可知道动作是否生效；反馈只表达实际达到的阶段，避免把「准备复制/移动」说成文件已写入目标。

需求合理，但「现有操作完全没有视觉反馈」不符合源码：复制、剪切、复制路径已有状态栏文字；排序有菜单和勾选，导航及隐藏切换也会改变列表。本需求是补充容易察觉的结果提示，保留原有状态栏和菜单。默认开启，不增加设置项。

## 边界：明确不改什么

- 只覆盖下述六类操作，不把所有 `a.status` 全局转成 Toast，不创建通知中心、历史、队列配置或新的通用事件系统。
- 不新增或改变动作、默认键位、400ms 双击规则和改键优先级，不在按键原始事件中硬编码 c/x 等触发提示。
- 不改变复制/移动/粘贴、ZIP 只读、起点回退和排序的业务规则；仅修正本范围内空操作的成功误报，并为反馈补齐必要的完成判定。
- 不扩展粘贴、删除、安装应用、自定义命令、普通导航等操作的 Toast；复制路径共用函数的其他调用不自动获得本需求的提示。
- 不引入依赖或插件，不升级 MyGo；不加装饰动画、轮询、常驻计时 goroutine、后台保活或文件检查任务。
- 本阶段只修改本 PRD 与 AGENTS.md 的文档索引；不改代码、README、官网、CHANGELOG、版本、其他 PRD 或 docs/plan.md 修订编号；只提交、推送自己的功能分支，不创建 PR、不合并、不关闭 issue、不发版。

## 1. 已核实的代码事实

### 动作与键位

依据 `gui/actions.go` 的 `actions()`、`defaultKeys()`、`keymapWithOverrides()`。表中仅记录默认值，实际执行以有效动作表为准；六个动作均可重映射或解绑，Vim 开关不改变它们。默认表叠加自定义命令，再叠加 `keymap.json`，用户覆盖优先。

| 用户提到的键 | 实际动作 ID | 默认其他键 | 当前行为与已有反馈 |
|---|---|---|---|
| c | `copy` | ⌘C | `run` 把 `chosen()` 路径放入应用内部 `a.clip`，不是系统文件剪贴板；状态栏「已复制 N 项，到目标文件夹按…粘贴」。没有写入目标文件。 |
| c c（双击） | `copypath` | ⌘⌥C | `copyPathText` 通过 `Services.WriteClipboard` 写入文本，记录 `a.copied`，状态栏「已复制路径」。现有接口无成功回执。 |
| x | `cut` | ⌘X | ZIP 内先由 `readOnly` 拒绝；其他情况登记内部路径及 `clipCut=true`，到粘贴时才移动；状态栏目前写「已剪切」。 |
| `（反引号） | `go.start` | 无 | 当前窗格自定起点存在且是目录则导航，否则回退主目录；没有专门结果句。 |
| , | `sortmenu` | 无 | `popup("sort")` 只打开菜单；选中项目才修改排序字段，不能宣称打开即排序完成。 |
| . | `hidden` | ⌘⇧. | `ToggleHidden()` 同步切换当前窗格隐藏文件可见性并调整光标；列表变化，无专门结果句。 |

`chosen()` 是「有效多选，否则光标行」；没有显式多选不等于没有目标。只有多选与光标都没有有效条目时才为空。`copypath` 对这种空目标会复制当前目录；有条目时按现有顺序以换行分隔，不改变路径格式。ZIP 虚拟路径保持 `/archive.zip!/sub` 等现有字符串语义，不承诺它是系统可直接打开的实体路径，也不把复制字符串变成文件存在性验证。

`gui/view.go:dispatch` 与 `internal/keymap/keymap.go` 已等待双击：首个 c 尚未执行 `copy`；400ms 内第二次 c 只执行 `copypath`；到达 400ms 才执行单键；另一按键先刷新等待中的单键。不能先提示「已复制」再改成「已复制路径」。重映射后也沿用有效键位表的同键双击判断。动作触发后提示，文案不含写死快捷键；若未来必须展示键名，应从有效键位表读取。

### 操作完成的证据

- `copy/cut` 现状即使 `chosen()` 为空仍清空内部剪贴板并写「已复制/已剪切 0 项」；本需求建议空目标先返回、不改原剪贴板，只给非成功反馈。
- `readOnly` 已在状态栏解释 ZIP 只读。ZIP 可复制以便稍后解压，也可复制虚拟路径文本；不可剪切。
- `pane.Tab.Go()` 只比较和设置路径，不验证读取成功。`navigate` → `afterNav` → `load` 异步列目录，`load` 以 `ts.seq`、目录快照丢弃旧结果；失败写 `ts.err`，列表显示「无法读取」。不能在调用 `navigate` 后立即提示「已回到起点」。
- 已在目标目录时 `Go()` 返回 false；起点不存在或不是目录会回退主目录。`goHomeSub` 取主目录失败目前静默返回。
- 排序入口有三处：`app.go:popMenu`（逗号菜单）、`chrome.go:sortMenu`（界面菜单）、`menu.go:sortItems`（原生菜单栏）。它们写 `ts.sort`；`view.go:table` 才将变化同步到 `ts.t.SetSort`。不应仅在一个菜单或每次构建 table 时播报。
- `gui/view.go` 每次构建保存 `Services`，不应为本需求把 `Context` 或 Toast 元素存入 app 或工作线程。

## 2. 锁定 MyGo v0.8.3 的 Toast 调研

通过 `go list -m -f '{{.Dir}}' github.com/egoist/mygo` 找到锁定模块。以下路径相对该模块，最终 API 以本地源码为准：

| 证据 | 核实结果 |
|---|---|
| `ui/api_gen.go`、`ui/toast.go` | 提供 `Context.Toast`、`AddToast`、`CloseToast`，以及 `ui.ToastViewportBase`、`ui.ToastBase`。 |
| `ui/toast.go:Toast`、`life` | `Timeout=0` 为 4 秒；负数永不自动关闭；可指定正时长；带操作按钮的 `ToastAction` 默认 8 秒。 |
| `AddToast`、`Toast` | `Toast(message)` 以消息同时作为 ID 和标题；同 ID 原位替换、重新计时，不移动队列位置；空 ID 自动生成新项。每次 AddToast 都请求读屏播报标题及描述。 |
| `toastViewport` | 最多显示最新 3 条、旧项仍留存并继续计时；新项关闭时未过期的旧项可能再次出现。因此「只画最新一条」不等于删除其他项。 |
| `buildToasts` | 默认底部居中，距窗口底部 `Theme.Space(6)`，逆色背景和文字，圆角、阴影；没有向上位移动画，但开头和末尾各有 200ms 透明度动画，会请求动画帧。默认有小内边距，未限定为项目 caption。 |
| `toastViewport`、`ToastBase` | viewport 是全窗 overlay 的穿透列；Toast 根有 hover，默认会接收指针。悬停、或窗口有焦点时 Toast 内有键盘焦点，会暂停全组 Toast 的计时；后台/隐藏时通常继续，悬停仍可暂停。时间已过的条目恢复显示前被移除。 |
| `AddToast`、`ToastBase` | AddToast 不移动键盘焦点；Toast 根有 `RoleStatus`，标题/描述由 `Announce` 播报。按钮可 Tab 到达；Toast 内有焦点时 Esc 才关闭。纯文字提示无需按钮。 |
| `toastViewport`、`ui/headless.go` | 到期通过 `c.After` 请求帧，无需应用轮询；Tester 有 `Advance`、`SetFocused`、`Clipboard`、`FailClipboard`、`Announcements`。 |
| `ui/context.go`、`ui/services.go` | `Services.WriteClipboard` 无错误回执；`Context.WriteClipboardThen(text, done)` 能确认结果，回调后框架请求重建。Services 没有对应 Then 方法，不能假设存在。 |
| `ui/doc.go`、维护技能 | Context 只在当前构建/输入生命周期使用；元素和 Toast parts 会过期。持久状态只存文本、ID、序号等业务数据；后台结果经 `a.post` 回 UI 线程。 |

在线参考为用户给出的 [MyGo Toast 文档](https://mygo.run/docs/ui/toast)。2026-11-13 web fetch 返回不可访问后，用只读 HTTP GET 获取成功；所见文档包含同类 API 和自定义 viewport 示例。在线示例的 Transition 不采用；以上结论均对照本地 `docs/ui/toast.md`、`ui/toast.go` 和 `ui/api_gen.go`，不把网站当前版本当成 v0.8.3 的保证。读屏、悬停、后台和计时的框架测试依据为 `ui/toast_test.go`；剪贴板成功/失败测试见 `ui/pointer_device_test.go:TestWriteClipboardThen`。本阶段没有运行或修改框架测试。

## 3. 建议的最小产品规则（待 Claude 裁定）

### 提示内容与触发时机

| 操作 | 建议提示 | 必须达到的阶段 / 失败或空操作 |
|---|---|---|
| `copy` | 「已复制 N 项，待粘贴」 | 有有效目标并登记内部剪贴板后；只代表受理，不代表文件复制完成。空目标「没有可复制的项目」，不清空旧剪贴板。 |
| `cut` | 「已标记 N 项待移动」 | 有目标且非只读，登记后；明确文件尚未移动。空目标「没有可剪切的项目」；ZIP「压缩包内不能剪切」，保留原只读说明，不改变剪贴板。 |
| `copypath` | 「已复制路径」；无条目时「已复制当前目录路径」 | 系统文本写入成功回执后。失败「复制路径失败」，状态栏给原因；无窗口服务时不发成功提示。`a.copied` 仅是测试/请求记录，不是系统成功证据。目录有效但为空可以成功复制目录；目录字符串为空则拒绝。 |
| `go.start` | 「已回到起点」 | 对本次目标的列目录成功且仍是当前有效请求后。自定起点失效并回退，成功后「起点不可用，已回到主目录」。未设自定起点、直接使用主目录时可用普通成功文案。 |
| 已在起点 | 「已在起点」 | 当前目录相同且已成功加载，无需重新读盘。若当前正在加载，等现有有效加载结果；若当前有读取错误则不报告成功，沿用失败说明。 |
| 起点导航失败 | 「无法回到起点」 | 取主目录或读取目标失败时；状态栏/列表保留具体原因。旧请求被新导航取代则不提示，不能把后来读入的其他目录算成回到起点。 |
| `hidden` | 「已显示隐藏文件」 / 「已隐藏隐藏文件」 | 切换实际状态后，即使目录里没有隐藏项也成立；不宣称文件被创建或删除。若列表原本有读取错误，提示只表达显示选项已切换，不报目录读取成功。 |
| `sortmenu` 后排序改变 | 「排序：名称 · 升序」等 | 建议**打开菜单不额外 Toast**；选择后比较前后 column/descending，有变化且已应用到窗格排序才提示。选择同项、Esc 取消、只打开菜单均不提示成功。即使列表为空，排序状态确已改变仍可提示。 |

上述失败/空操作提示只覆盖这六类，不把其他错误转换为 Toast。状态栏已有详细信息仍保留；仅将本范围内「剪切已完成」和「0 项成功」等误导文案改为符合实际阶段的文字。提示不展示全路径、文件名或快捷键，保持短小；多项只显示数量，避免长文件名撑大浮层。

**排序建议的取舍**：Issue 字面列出了逗号，但菜单出现已有明确反馈，额外显示「已打开排序菜单」重复且可能遮挡菜单，因此建议仅在真正改变排序时显示。三处菜单共用一个小的比较/应用帮助方法，保持各入口一致；不新增 `sort.*` 快捷键动作，不改变工作区恢复排序时的提示。该选择及相应的有限菜单文件改动须由 Claude 明确接受或改写。

### 展示、连按与可达性

1. 窗口底部居中，放在现有状态栏顶部上方，间距取 `px("space-2")`。不在屏幕正中，不挤动列表布局，不遮住状态栏及键位提示。底部偏移由实际状态栏高度加 token 间距得出，不写死三行高度。
2. **建议时长 1.2 秒**，立即出现、到期立即消失，不向上飞入、不淡入淡出。这里将「向上浮出」解释为底部上方浮层的位置，不引入项目禁止的装饰动画；若坚持框架默认淡入淡出，必须由 Claude 明确裁定此规范例外。
3. 同一窗口仅保留本需求一个固定 ID（例如 `shortcut-feedback`），不同结果覆盖前一次并重置时长；不按文案创建多个 Toast，不堆叠或排队。不用 `CloseToast("")` 误关未来其他功能的提示。
4. 同一结果快速重复：建议已显示期间不再次 AddToast、不续时、不重复读屏播报；原提示到期后，下次实际动作可重新显示。不同结果立即替换并重计时。这样不需要第二套计时器或私有 API，见 §4 D2。停止操作后不能残留多条提示或播放过时历史。
5. 首个 c 等待双击时绝不反馈。400ms 内 c c 仅出现路径反馈；单 c 到期后才出现复制反馈。c 后另一键使单键先执行，允许它短暂显示，再由后续有效结果覆盖；不额外延迟文件操作。长按/自动重复仅对实际执行的动作给反馈，不改变原派发语义。
6. 不 Focus/AutoFocus、不 Modal，不添加按钮或 Tab 停靠点。viewport 及提示根应使用受支持的穿透能力，让点击、滚动、文件拖入/拖出不被提示截走；同位置拖放须实测。不要只凭 viewport 默认穿透就断言子根也穿透。
7. 保留 ToastBase 的 status 角色和 AddToast 的读屏播报，不只靠颜色。状态栏保留结果，便于短提示消失后查看；不复制调用 Announce 形成双重播报。建议保留框架悬停暂停计时语义，穿透后实际 hover 行为须测试确认；「快速消失」指无连续操作/悬停暂停时的 1.2 秒。不要为绝对到期再引入独立 timer。
8. 小号单行文字使用 `caption`，内边距 `space-1.5` / `space-3`，圆角 `radius-control`，灰阶 `surface-200` 配 `ink`，不加图标、品牌青、阴影或渐变。宽度随短文案，最大为窗口宽减两侧 `space-4`；窄窗允许收缩，不越界。颜色、字号、间距均用现有 `tok()`/`px()` 和字体样式帮助方法。

## 4. 最小实现路径与待审查事项

以下仅为实现建议，未经 Claude 放行不能动代码。

- `gui/feedback.go`（预计新增）：只放本需求的待显示文本/结果序号、固定 ID 的提交方法、最小 viewport 绘制；用 MyGo 的 Toast 管理计时、status 语义和到期，不实现第二套通知系统。
- `gui/app.go`：app 增加小量纯数据状态；在 `run` 的实际动作分支登记结果，空目标先退出；起点导航记录目标窗格及期望 load 序号，在既有 `load` 结果接受后完成反馈。新导航、刷新或被替代 load 需失效/更新标记，不能将普通 load 都变成提示；不增加额外 ReadDir。目标已在当前目录时区分已载入、载入中和错误。
- `gui/view.go`：构建内消费待处理结果一次，然后 `c.AddToast(ui.Toast{ID: 固定值, Title: 文案, Timeout: 正时长})`；用 `ToastViewportBase` + `ToastBase` 只替换默认阴影和动画外观，复用框架生命周期，不持有它们返回的元素/parts。注意 `dispatch` 在现有 view 末尾，保证本帧晚产生的请求也能在框架后续 pass/frame 消费，不能要求再按一次键才显示。
- `gui/app.go:copyPathText` 与 `gui/view.go`：建议仅为 `copypath` 增加一次性文本写入请求，构建时用 `c.WriteClipboardThen`，回调只保存结果，下一次构建提交提示；不捕获 Context/元素。保留其他共用函数调用的现有范围；避免一次复制同时走旧 Services 写入和新的 Then 写入。无服务的直接业务测试通过可注入的小回执边界验证，不假造系统写入成功。
- `gui/app.go:popMenu`、`gui/chrome.go:sortMenu`、`gui/menu.go:sortItems`：若接受排序建议，复用小帮助方法完成实际排序状态改变与结果登记，不从 `table` 的每次渲染派生通知，工作区恢复不提示。
- `gui/feedback_test.go`（预计新增）、必要的既有 keys/workflow/chrome 测试：覆盖本需求；不复制测试框架内部实现。现有 token 足够，不新增设置、配置字段或 design tokens。

**Claude 必须裁定，不能隐藏为已解决的细节：**

- **D1 外观与时长**：建议最小自定义 viewport、1.2 秒、无动画无阴影，保留框架 Toast 管理。默认组件虽已底部居中，但 4 秒/动画/阴影不符合本项目，因此自定义有明确必要。
- **D2 重复提示与读屏**：本地 AddToast 每次都会 Announce，无公开「只刷新时间不播报」参数。推荐采用 §3.4 的同文案不续时、不重播，到期后下次动作可重新显示；不同文案同 ID 替换并重计 1.2 秒。可用无副作用的 OnClose 清理当前文案标记；替换时仍核对当前 ID/结果代号，不存 Toast parts 或额外计时器。不为严格滑动续时复制框架 timer 或操作私有状态。若要求每次操作重置计时，则明确接受重复播报并写出可测规则。两者不可同时宣称做到。
- **D3 排序反馈**：建议只在真实改变后提示、覆盖三处入口；打开菜单不提示。明确是否接受该解释与文件范围。
- **D4 完成边界**：建议采用可确认的剪贴板回执及起点有效 load 结果，不把调用请求当成功。针对回执乱序，用本请求序号防旧完成覆盖较新的结果；旧系统写入无法取消时不宣称可回滚实际剪贴板。导航被取代/窗格切换后，建议丢弃旧窗格提示。确定对自定起点失效回退的短文案和空复制不清空旧内容的修正。
- **D5 指针和暂停**：viewport 与根穿透、无按钮仍能保留 status/读屏；需要 UI 拖放与原生窗口确认。若穿透与 hover 暂停不能兼得，优先不阻塞操作，允许不暂停并在审查稿写明，不加第二套计时器。

## 5. 生命周期、线程和资源约束

- 所有提示状态只在主线程更新；后台目录读取沿用 `a.async` / `a.post`。Context、Element、ToastParts 不进入 app 长期状态或 goroutine，持久剪贴板服务仍遵守维护技能。
- 每次构建先领取/清除待处理请求再执行一次性副作用，重建多次不得重复写剪贴板、重复 AddToast 或无限请求帧。只保存最新的本需求结果，不按键次数积累无界切片。
- 导航、剪贴板结果带本需求的小序号/目标快照，旧结果不能覆盖更晚操作的提示；更新时钟由框架驱动。同 ID 替换后旧到期时间不能提前关闭新结果。
- 复用框架的 `c.Now()`、`c.After` 和 Toast 生命周期；应用不写 `time.AfterFunc`、ticker、sleep 或常驻 goroutine。Toast 关闭后没有自有定时资源；框架空 viewport 可以保留，但不得主动连续请求帧。

- 错误保留在原状态栏/列表，不用短 Toast 替代错误详情。未改动范围内的状态栏结果、快捷键提示、焦点和拖放规则保持原样。

  - 主目录取不到：「无法回到起点」。
- `copy`/`cut`：没有目标（多选和光标都没有有效项）时提示「没有选中的项目」，**不清空原剪贴板**。这是修正现在「已复制 0 项」的误报，属于本需求范围。ZIP 内 `cut` 沿用 `readOnly` 的状态栏说明，提示「压缩包内不能剪切」。
- 提示文案定为：
  - `copy`：「已复制 N 项」，`cut`：「已剪切 N 项」，`copypath`：「已复制路径」。状态栏里「到目标文件夹按…粘贴」的完整说明保留，提示只放这一句短的。
  - `hidden`：「已显示隐藏文件」/「已隐藏隐藏文件」；
  - 排序：「按名称升序」这类。
  文案里不写文件名、路径或快捷键。

**D5 指针与暂停：接受框架默认。** 视口本来就 `PassThrough()`；`ToastBase` 根节点悬停暂停计时的行为沿用。提示不加按钮、不抢焦点。只用一个 UI 测试确认提示显示期间点击下面的文件行仍然有效，不要求原生拖放实测。
