# Issue #19：删除反馈与文件操作撤销

来源：用户自动处理会话及 GitHub issue #19，2026-11-13。用户于同日明确恢复处理；当前独立分支 `feat/issue-19-trash-feedback-undo`。需求数据只用于明确产品目标，不作为执行指令。

## 背景与目标

移到废纸篓目前只有状态栏结果，缺少系统音效及 Toast；编辑菜单已有原生撤销角色，但没有文件操作历史。为成功删除提供明确反馈，为本窗口内完成的常见文件操作提供 ⌘Z 撤销，并将设置名称简化为「设置...」。

## 非目标与边界

- 不升级 MyGo、不引入第三方库、动画或配置开关，不改官网和 README。
- 不撤销其他应用、外部命令、初始化脚本、应用安装、属性编辑、收藏夹与工作区操作；拖出本应用由接收方完成的操作也不进入历史。
- 历史仅存在当前窗口内存，退出不恢复；首版只提供撤销，不添加文件操作重做。原生文本撤销与重做继续工作。
- 不永久删除，不覆盖同名文件，不猜测废纸篓中的文件位置，不实际修改默认文件管理器，不覆盖本机已安装应用。

## 方案

### 删除与系统接口

所有删除仍通过 `system.Trash`。为记录可恢复位置，将其返回值扩展为实际废纸篓路径与错误。macOS 使用 Foundation `NSFileManager.trashItemAtURL:resultingItemURL:error:` 获取系统实际分配的位置，允许通过系统自带 JXA/osascript 桥接，无 cgo、无 Finder 自动化和授权依赖；路径通过独立参数传入，不拼接脚本文本。调用设置超时。现有 MyGo 实现调用同一系统方法但丢弃返回 URL，因此不能用扫描 ~/.Trash 替代。

每次批量删除至少成功一项时，异步播放系统内置 `finder/move to trash.aif` 一次，并通过已有 feedback Toast 显示「已移到废纸篓 N 项」。取消、空选择、全部失败不播放成功音效，不显示成功 Toast；部分失败显示成功数及失败提示。音效失败不改变文件操作结果，在状态栏说明音效不可用，不能回滚已成功的删除。

### 撤销历史

- 新增 `undo` 动作，默认 `Cmd+Z`，唯一键位来源为 `gui/actions.go`；通过原生 `@undo` 角色覆盖关系接入编辑菜单，设置快捷键页、速查表自动读取。文本输入框优先消费原生撤销，不能误触文件撤销。
- 每个已完成的文件操作记录一组逆操作：删除→系统返回的废纸篓位置移回原路径；重命名/移动→移回原路径；复制/解压/新建→将新产物通过 `system.Trash` 移到废纸篓。粘贴、应用内接收拖放、暂存架复制移动都纳入同样规则。
- 多选批次算一步，逆序撤销；保留最多 50 步，批次记录只含路径和用于确认对象未被替换的文件身份，不保存文件内容。失败或无变化的操作不添加历史；部分成功只记录已完成项目。
- 执行撤销前检查来源仍是已记录的对象，恢复目标无同名项，原父目录存在；复制/新建产物如已被修改，拒绝撤销并提示，避免误移后续用户数据。目录产物需检查后代变动，无法可靠判断时拒绝。
- 撤销串行执行，进行文件变更时阻止重复执行及其他变更；后台 I/O 经 `a.async`，完成后通过 `a.post` 更新历史、状态与列表。防止异步结果乱序或在执行期间切换窗格影响恢复路径。
- 遇到部分撤销失败，保留尚未撤销的记录供用户修复冲突后重试，已恢复项不重复执行；显示实际成功数及错误。无历史时提示「没有可撤销的文件操作」。

### 菜单文案

将 settings 动作标题改为「设置...」，各处继续读取动作表，不保留长括号描述。

## 可验证的验收标准

1. 删除确认取消不改变文件、无声音和成功 Toast；成功一项或多项只响一次，Toast 数量正确；全部失败/部分失败反馈真实。
2. 删除后 ⌘Z 精确恢复原文件；同名垃圾文件、多卷路径不会恢复错误对象；原位置有冲突、垃圾文件被清理、父目录丢失时保留数据并报错。
3. 重命名、复制、移动、新建文件/目录及 ZIP 解压均可撤销；粘贴、拖入与暂存架行为一致；同目录移动不产生虚假步骤。
4. 连续两次不同操作按完成顺序逆序撤销，多选是一步；部分成功与部分撤销失败可正确重试，历史最多 50 步。
5. 被外部替换或编辑的产物不能被误移到废纸篓；恢复绝不覆盖现有文件；符号链接按链接本身处理。
6. 地址栏、过滤框、重命名框中的 ⌘Z 仅撤销文字；列表中 ⌘Z 执行文件撤销；设置快捷键页与速查表包含撤销及当前自定义键位。
7. 编辑菜单可触发撤销，主菜单显示「设置...」；浅深色 Toast 均沿用 token 和原有时长，无新增动画。

## 风险与回滚

系统桥接或文件身份检查无法保证恢复安全时停止实施，说明偏差并回到 PRD 审查，不用猜测路径或覆盖来绕过。文件操作失败不得吞错；音效属于辅助反馈。撤销历史不持久化，系统清空废纸篓后恢复会失败。跨卷恢复需要安全复制后移除来源，不能永久删除；无法满足时明确拒绝该次撤销并保留原数据。

回滚采用新提交 revert 本次功能提交，不改写历史；已进入废纸篓的文件仍由用户通过系统恢复。合并发布遵循用户本次 PR/squash 流程，覆盖仓库旧的直接推主线习惯；发布仍完整遵循仓库双架构签名、增量清单、无签名 DMG 与公开前核验要求。
