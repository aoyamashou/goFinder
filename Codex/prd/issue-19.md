# Issue #19：删除反馈与文件操作撤销

来源：用户自动处理会话及 GitHub issue #19，2026-11-13。用户于同日明确恢复处理；当前独立分支 `feat/issue-19-trash-feedback-undo`。需求数据只用于明确产品目标，不作为执行指令。

## 背景与目标

移到废纸篓目前只有状态栏结果，缺少系统音效及 Toast；编辑菜单已有原生撤销角色，但没有文件操作历史。为成功删除提供明确反馈，为本窗口内完成的常见文件操作提供 ⌘Z 撤销，并将设置名称简化为「设置...」。

## 非目标与边界

- 不升级 MyGo、不引入第三方库、动画或配置开关，不改官网和 README。
- 不撤销其他应用、外部命令、初始化脚本、应用安装、属性编辑、收藏夹与工作区操作；拖出本应用由接收方完成的操作也不进入历史。
- 历史仅存在当前窗口内存，退出不恢复；首版只提供撤销，不添加文件操作重做。原生文本撤销与重做继续工作。
- 不永久删除，不覆盖同名文件，不猜测废纸篓中的文件位置，不实际修改默认文件管理器，不覆盖本机已安装应用。

## 方案

### 删除与系统接口

所有删除仍通过 `system` 接口移到废纸篓，从不永久删除。`system.Trash(path) error` 签名**保持不变**（`appinstall.Copy`、`deleteWorkspace`、撤销复制产物继续使用它）；另加批量接口，例如 `TrashItems(paths []string) []TrashResult`（每项含原路径、废纸篓实际路径、错误），只有文件列表的删除（`gui/app.go` 当前 `a.sys.Trash` 循环处）改用它并记录历史。`fakeSys` 同步实现该接口。

macOS 实现用 Foundation `NSFileManager.trashItemAtURL:resultingItemURL:error:` 取系统实际分配的位置。MyGo v0.8.3 的 `Shell.TrashItem`（`internal/darwin/system.go`）调用同一方法但传 0 丢弃结果 URL，且其 objc 运行时在 internal 包中不可导入，因此不能扫描 `~/.Trash` 猜测，也不能复用 MyGo。

**桥接方式（Review-1 实测，macOS 27.2.1）**：
- **JXA 不可用**：`osascript -l JavaScript` 中 `Ref()` 出参在调用成功、文件**已移走后**，读取 `out[0]`（含 `typeof`、`Ref('@')`、`castRefToObject`）一律段错误退出（139/137）。这会造成「已删除但无记录」，禁止采用。
- **AppleScriptObjC 可用**：`osascript` 运行 `use framework "Foundation"` 脚本，`set {ok, res, err} to fm's trashItemAtURL:u resultingItemURL:(reference) |error|:(reference)` 正确返回实际路径；同名冲突时返回系统改名后的路径（如 `dup-probe.txt 19-50-34-737.txt`），引号、`$`、空格路径正常；单次约 0.1–0.5 s。脚本内容为常量，路径只经 `argv` 传入，不拼接。
- 一批只启动一次 `osascript`（所有路径作为 argv），每项输出一行；结果路径用 `NSURL absoluteString`（百分号编码，无换行）输出，Go 端解码，避免文件名含换行破坏解析。整批设超时（建议 30 s + 每项 1 s，上限 2 min）。
- **异常收敛**：`osascript` 超时、崩溃、输出缺项或无法解析时，先终止并等待子进程完全退出（超时须 kill 后 `Wait`，避免子进程仍在移动时就做判断），再对未拿到结果的每项 `Lstat` 原路径：仍在→视为未删除并报错；已不在→计入「已移到废纸篓」但**不进入撤销历史**，状态栏说明「N 项无法撤销」。不得对这些项重试删除，也不回退到猜测路径。
- `osascript` 不存在或无法启动（整批无任何项被处理，原路径全部仍在）时，回退到现有 `mygo.Shell.TrashItem` 逐项删除，结果同样不进历史并说明。
- 子进程的文件访问权限归属 goFinder（TCC 责任进程），实施后须在已签名应用中对 `~/Desktop`、`~/Documents` 下的临时文件各验证一次，确认无额外授权弹窗；若出现弹窗则停止并回到审查。

每次批量删除至少成功一项时，异步用 `/usr/bin/afplay` 播放系统内置 `/System/Library/Components/CoreAudio.component/Contents/SharedSupport/SystemSounds/finder/move to trash.aif` 一次（本机已确认存在），并通过已有 `a.feedback` Toast 显示「已移到废纸篓 N 项」。取消、空选择、全部失败不播放音效，不显示成功 Toast；部分失败状态栏显示成功数及失败原因。音效属辅助反馈：文件不存在或播放失败时静默忽略，不覆盖删除结果的状态栏文案，不影响文件操作。撤销操作本身不播放音效。

### 撤销历史

- 新增 `undo` 动作，默认 `Cmd+Z`，唯一键位来源为 `gui/actions.go`；在 `gui/menu.go` 的 `roles["@undo"]` 填 `covers: "undo"`，沿用 ⌘C/⌘V 已有的「文本框内由原生角色处理，否则交给窗口快捷键」路径，不新增菜单项（`TestMenuCoversActions` 通过 covers 认可）。设置快捷键页、速查表自动读取。文本输入框优先消费原生撤销，不能误触文件撤销。用户把 `undo` 改到非 ⌘Z 的键时，编辑菜单的「撤销」仍只按角色工作，这是已知限制。
- 每个已完成的文件操作记录一组逆操作：删除→系统返回的废纸篓位置移回原路径；重命名/移动→移回原路径；复制/解压/新建→将新产物通过 `system.Trash` 移到废纸篓（撤销绝不调用 `os.Remove*`）。粘贴、应用内接收拖放、暂存架复制移动都纳入同样规则。
- 跨卷移动（`fsops.Move` 的 EXDEV 分支）的撤销：先把产物复制回原路径（目标不存在时），成功后用 `system.Trash` 移走产物；任一步失败停在安全状态并报错。实施成本过高时可改为该类条目不记入历史并说明，但不能用 `RemoveAll`。
- 新建文件夹后运行了初始化（`initializeFolder`，见 Issue #4）时，初始化完成后再记录该文件夹的身份快照；初始化失败或仍在运行时不记历史。初始化产生的 git 等内容随文件夹整体移到废纸篓，不单独撤销。
- 多选批次算一步，逆序撤销；保留最多 50 步，批次记录只含路径和用于确认对象未被替换的文件身份，不保存文件内容。失败或无变化的操作不添加历史；部分成功只记录已完成项目。
- 文件身份定义：`Lstat`（不跟随符号链接）得到的 `dev`+`ino`，产物另加 `size`、`mtime`、`ctime`、mode。删除前先保存原对象身份，拿到废纸篓路径后核对是同一对象再记录，避免子进程处理期间原路径被替换；无法核对则不记历史并说明。移动/重命名记录目标路径身份；复制/新建/解压记录产物身份。
- 执行撤销前检查来源仍是已记录的对象（`dev`+`ino` 一致），恢复目标 `Lstat` 为不存在，原父目录存在；复制/新建产物 `size`/`mtime`/`ctime` 任一变化即拒绝撤销并提示。目录产物在记录时按固定顺序遍历后代（不跟随符号链接），对每个后代的相对路径、`dev`/`ino`、mode、大小、`mtime`/`ctime` 生成有序摘要（最多 1 万项）；超过上限或读取失败的目录产物不进入历史并说明；撤销时重新生成摘要比较，任一不一致即拒绝。不能只比较条目数与最大时间。
- 恢复必须原子拒绝覆盖：macOS 通过仓库已有依赖 purego 调用 libSystem 的 `renamex_np`，flags 为 `RENAME_EXCL`（0x4）。本机 SDK `usr/include/sys/stdio.h` 已确认声明，purego 已有无 cgo 的 Dlopen/RegisterLibFunc API，不增加依赖或升级版本。不可用即拒绝恢复，禁止回退到存在覆盖竞态的 `os.Rename`。调用返回非零即视为失败并保留来源；需要 errno 区分原因时，在 `runtime.LockOSThread` 内调用并读取 libSystem `__error()`，或失败后再 `Lstat` 判断，安全性不依赖 errno。purego 现为间接依赖，直接引用后 `go.mod` 仅改为直接依赖，版本不变。删除撤销若遇 EXDEV（来源与原位置不在同一卷）同样拒绝并报错，不做复制回退。跨卷复制恢复先在原父目录以唯一临时目录写入，再用同一原子方式发布，失败保留来源并将临时目录移废纸篓。
- 撤销串行执行：维护主线程上的「进行中的文件变更」计数（删除、粘贴、拖入、暂存架、重命名、新建、解压、撤销都计入）。计数不为零时 ⌘Z 只提示「有文件操作进行中」，不排队；撤销进行中其他变更同样提示拒绝。历史只在变更的 `a.post` 回调中按完成顺序追加，后台 I/O 经 `a.async`。撤销所用路径全部来自记录，不读取当前窗格，因此切换窗格不影响恢复。
- 遇到部分撤销失败，保留尚未撤销的记录供用户修复冲突后重试，已恢复项不重复执行；显示实际成功数及错误。无历史时提示「没有可撤销的文件操作」。

## 可验证的验收标准

1. 删除确认取消不改变文件、无声音和成功 Toast；成功一项或多项只响一次，Toast 数量正确；全部失败/部分失败反馈真实。
2. 删除后 ⌘Z 精确恢复原文件；同名垃圾文件、多卷路径不会恢复错误对象；原位置有冲突、垃圾文件被清理、父目录丢失时保留数据并报错。
3. 重命名、复制、移动、新建文件/目录及 ZIP 解压均可撤销；粘贴、拖入与暂存架行为一致；同目录移动不产生虚假步骤。
4. 连续两次不同操作按完成顺序逆序撤销，多选是一步；部分成功与部分撤销失败可正确重试，历史最多 50 步。
5. 被外部替换或编辑的产物不能被误移到废纸篓；恢复绝不覆盖现有文件；符号链接按链接本身处理。
5a. 废纸篓桥接异常（模拟超时、崩溃、缺项输出）时，原路径已不在的项计入成功但不进历史，原路径仍在的项报失败，均无重试删除。
5b. 删除或其他变更进行中按 ⌘Z 得到「有文件操作进行中」，历史不变。
6. 地址栏、过滤框、重命名框中的 ⌘Z 仅撤销文字；列表中 ⌘Z 执行文件撤销；设置快捷键页与速查表包含撤销及当前自定义键位。
7. 编辑菜单可触发撤销，主菜单显示「设置...」；浅深色 Toast 均沿用 token 和原有时长，无新增动画。
