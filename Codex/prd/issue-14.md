# Issue #14：浏览 DMG 并安装其中的应用

> 来源：Codex 定时任务开发会话，2026-11-13；[Issue #14](https://github.com/aoyamashou/goFinder/issues/14)。
> 要改什么及为什么：打开 DMG 时在 goFinder 浏览挂载内容，右键 DMG 可选择并安装其中的 `.app`，减少手动切换 Finder；已挂载卷中的 `.app` 继续使用现有安装菜单。
> 边界：只处理本地 DMG 的挂载、浏览及安装入口；不更改一般文件复制、ZIP、应用包安装权限和隔离语义，不覆盖已有应用，不修改系统默认浏览器或用户已安装的 goFinder，不新增依赖。

## 背景与目标

当前 `gui/app.go:openEntry` 对普通 DMG 走 `sys.Open`，不把窗口导航到映像内容；已有 `gui/appinstall.go` 对有效本地 `.app` 提供打开、复制、复制并解除隔离，`contextMenuPre` 已对这种应用追加两个安装项。`internal/appinstall.Copy` 使用 `ditto` 暂存和 `xattr`，不覆盖已存在目标、不提权；已挂载的 DMG 内应用包本身无需新复制实现。本需求补齐从 DMG 文件到挂载内容的入口。

## 非目标

- 不实现 DMG 内虚拟文件系统、写入镜像、自动运行应用或自动卸载用户已有的卷；不支持 ZIP 内 DMG、非本地映像、DMG 中的 `.pkg` 自动安装。
- 不改已有 `.app` 安装的目标、同名拒绝、隔离选项和权限行为；不自动运行 `sudo`，不读取密码；不修改快捷键、菜单栏、README、官网或用户配置格式。
- 不对镜像内容做全盘递归扫描、自动执行脚本或绕过系统安全检查；安装来源仅由用户明确选择。

## 方案

1. 对常规本地 `.dmg`（扩展名大小写不敏感，排除 ZIP 内路径及目录）提供后台挂载。`openEntry` 的打开键/双击调用同一挂载入口；挂载成功后用现有 `navigate` 进入返回的挂载点，沿用原列表、键盘和安装行为。已有挂载应复用，不主动卸载用户已有卷。读取/挂载失败在状态栏反馈，原目录不变；异步结果必须防止已切换窗格、目录、工作区或窗口关闭后导航到错误位置。
2. DMG 文件的右键菜单固定追加「复制到『应用程序』」与「复制到『应用程序』并解除隔离」，调用后台挂载和查找，再走既有安装服务。命令快照使用右键目标路径和所选模式，不能误用当前光标或多选。挂载前仅列出可见选项，不扫描、不写磁盘；取消菜单不挂载。
3. 安装入口只检查挂载根目录直接子项，依据现有 `appinstall.Bundle` 识别真实目录 `.app`，不沿符号链接；不检索嵌套目录。零个时提示没有可安装应用；恰有一个直接安装；多个时在主线程显示明确的应用选择菜单，允许取消，绝不猜测或批量安装。采用项目既有菜单与焦点机制；选中时重新检查挂载点和应用，复制前不运行应用。已挂载卷中 `.app` 的原有右键两项和打开菜单继续有效。
4. 在可替换的系统接口中封装磁盘映像操作，命令使用 `/usr/bin/hdiutil` 固定参数和独立 argv，不经过 shell。使用 `attach -readonly -nobrowse -plist` 的结构化 plist 结果识别**实际卷挂载点及设备**，不依赖 DMG 名称猜路径、不解析命令输出的自然语言；处理多分区、空挂载点和不支持的/加密映像时明确失败，不自动输入密码。读取 `hdiutil info -plist` 或等效官方信息识别已有挂载与其设备，不能把名称相同的不同映像视为同一文件。耗时操作在 `a.async`，主线程经 `a.post` 更新。
5. 挂载生命周期：标记本应用本次成功新建的挂载和设备，已有卷不可自动卸载。供浏览的卷在离开其所有可见窗格及后台安装任务后，或程序关闭时尽力安全卸载；右键直接安装的临时卷在复制及结果处理结束后安全卸载。多任务引用和并发打开不得重复卸载；只对精确记录的设备发普通 detach，不 `-force`，卸载失败要提示卷位置并允许用户手动推出，不删除挂载内容。若现有窗口关闭回调/导航模型无法可靠保证上述生命周期，先记录偏差、退回审查，不用不安全的后台清理代替。
6. 提示复制的状态和失败细节沿用现有安装结果；有多个卷或重复 app 名称时选择项需附卷名称/相对位置以可区分。禁止覆盖目标、禁止把 `/Applications/goFinder.app` 通过本机测试复制覆盖。安装源在挂载失效或外部卸载后失败时真实报告，不尝试清理其他卷。

## 涉及文件（预计）

- `gui/app.go`、`gui/appinstall.go`、`gui/view.go`、`gui/sys.go`：打开与右键入口、系统接口、后台请求与状态更新。
- 新增 `internal/dmg`：DMG 识别、plist 解码、卷/设备与归属、根目录应用列表、可注入命令执行器；避免 MyGo 依赖，优先复用已有 plist 能力，不能引入新第三方库。
- 按实际改动扩展 `gui/*_test.go`、`internal/dmg/*_test.go`，并更新 `docs/plan.md`、本 PRD 实施记录及设计规范（如界面涉及新 token 才更新）。

## 可验证验收标准

- 打开本地有效 DMG 后仍在 goFinder 中浏览其真实挂载点；当前列、父列及子列、键盘及鼠标入口作用于正确项目；切换目录/窗格后的过期挂载结果不劫持用户位置。
- 根目录一个有效 app 时，DMG 两个右键选项分别以保留隔离和解除隔离模式调用既有安装器；多个 app 可选择且取消无安装；无 app、格式无效、只含符号链接、密码/损坏/不可读、卸载失败时有清楚结果且不误报成功。
- 已挂载 DMG 内的 app 仍显示既有三项打开菜单与两项右键安装；ZIP、普通文件、已安装应用和本机 goFinder 更新行为不回归。
- 不卸载非本应用新建的卷；共享挂载及异步任务中不提前卸载，结束后仅尝试卸载本应用拥有且不再引用的设备。路径有中文、空格、引号、前导 `-` 时不发生 shell 注入。
- 不在 UI 主线程执行磁盘镜像或复制；相同镜像的重复触发不造成重复任务、错误卸载或错误导航；挂载、扫描、复制、卸载任一失败均反馈正确阶段。

## 测试计划

- 单元测试使用伪命令执行器和 plist 夹具覆盖多分区、零/多应用、现有挂载复用、路径转义、错误、资源引用及 detach 所有权；临时目录模拟 app 和目标，不碰用户真实 `/Applications`。
- UI Tester 使用 `fakeSys` 覆盖双击/打开键、三列右键目标、多应用选择与取消、两种安装模式、失效请求及后台结果；验证不修改用户既有快捷键及正常应用打开。
- 使用临时目录内自主生成的最小只读 DMG 验证真实 `hdiutil` plist、挂载、根目录发现和卸载；只对测试创建的设备执行 detach，绝不修改系统默认设置或覆盖安装用户应用。记录未测试的加密及实际 Intel 机器限制。
- 执行 `gofmt -l gui internal`、`go vet ./...`、`go tool mygo vet .`、`go tool mygo vet ./gui`、`go test ./...`；共享状态运行 race 测试；新界面生成并检查浅色/深色截图；按项目约定 `Apple_self_dev` 签名双架构 build（不安装）。

## 风险与回滚

- DMG 挂载是系统资源，必须按所有权及引用关系跟踪；失败时仅保留可见的本次挂载并告知路径，不能强制卸载或删除他人数据。用户手动推出后进行中的复制可能失败，应报告失败且不修改源。
- 已有安装器的 `Lstat` 后重命名存在先前审查接受的小概率竞争，维持现有行为，不扩大覆盖能力。镜像不可信，绝不自动执行其中代码；解除隔离只对用户主动选择的副本按既有功能处理。
- 任一关键验收失败或无法安全判断卷归属则暂停、标记 `needs-human`；回滚通过普通 revert 相关合并提交，不改写主线、不永久删除用户数据。发布损坏时遵守现有更新签名和双架构分发恢复流程。
