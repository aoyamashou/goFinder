# Issue #14：浏览 DMG 并安装其中的应用

> 来源：Codex 定时任务开发会话，2026-11-13；[Issue #14](https://github.com/aoyamashou/goFinder/issues/14)。
> 要改什么及为什么：打开 DMG 时在 goFinder 浏览挂载内容，右键 DMG 可选择并安装其中的 `.app`，减少手动切换 Finder；已挂载卷中的 `.app` 继续使用现有安装菜单。
> 边界：只处理本地 DMG 的挂载、浏览及安装入口；不更改一般文件复制、ZIP、应用包安装权限和隔离语义，不覆盖已有应用，不修改系统默认浏览器或用户已安装的 goFinder，不新增依赖。

## 背景与目标

当前 `gui/app.go:openEntry` 对普通 DMG 走 `sys.Open`，不把窗口导航到映像内容；已有 `gui/appinstall.go` 对有效本地 `.app` 提供打开、复制、复制并解除隔离，`contextMenuPre` 已对这种应用追加两个安装项。`internal/appinstall.Copy` 使用 `ditto` 暂存和 `xattr`，不覆盖已存在目标、不提权；已挂载的 DMG 内应用包本身无需新复制实现。本需求补齐从 DMG 文件到挂载内容的入口。

## 非目标

- 不实现 DMG 内虚拟文件系统、写入镜像、自动运行应用或自动卸载用户已有的卷；不支持 ZIP 内 DMG、非本地映像、DMG 中的 `.pkg` 自动安装。
- 不改已有 `.app` 安装的目标、同名拒绝、隔离选项和权限行为；不自动运行 `sudo`，不读取密码；不修改快捷键、菜单栏、README、官网或用户配置格式。
- 不对镜像内容做全盘递归扫描、自动执行脚本或绕过系统安全检查；安装来源仅由用户明确选择。

## 方案

1. 对常规本地 `.dmg`（扩展名大小写不敏感，排除 ZIP 内路径及目录）提供后台挂载。`openEntry` 的打开键/双击调用同一挂载入口；挂载成功后用现有 `navigate` 进入返回的挂载点，沿用原列表、键盘和安装行为。已有挂载应复用，不主动卸载用户已有卷。多卷时进入 plist 中第一个有挂载点的卷，状态栏提示共 N 个卷。读取/挂载失败在状态栏反馈，原目录不变；异步结果必须防止已切换窗格、目录、工作区或窗口关闭后导航到错误位置：发起时记下 `ts`、`ts.t.Dir` 和 `ts.seq`，回到主线程时任一不符就只在状态栏报告挂载位置，不导航。
2. DMG 文件的右键菜单固定追加「复制到『应用程序』」与「复制到『应用程序』并解除隔离」，调用后台挂载和查找，再走既有安装服务。命令快照使用右键目标路径和所选模式，不能误用当前光标或多选。挂载前仅列出可见选项，不扫描、不写磁盘；取消菜单不挂载。
3. 安装入口只检查挂载根目录直接子项，依据现有 `appinstall.Bundle` 识别真实目录 `.app`，不沿符号链接；不检索嵌套目录。零个时提示没有可安装应用；恰有一个直接安装；多个时在主线程显示明确的应用选择菜单，允许取消，绝不猜测或批量安装。采用项目既有 `popup`/`popMenu` 机制（新增一种 kind，菜单项快照为绝对路径，用户已离开原目录时仍按快照执行）；取消选择菜单时，若卷是本次为安装临时挂载的，同样卸载；选中时重新检查挂载点和应用，复制前不运行应用。已挂载卷中 `.app` 的原有右键两项和打开菜单继续有效。
4. 在可替换的系统接口中封装磁盘映像操作，命令使用 `/usr/bin/hdiutil` 固定参数和独立 argv，不经过 shell。使用 `attach -readonly -noautoopen -plist`（浏览用；右键安装的临时挂载另加 `-nobrowse`），stdin 置空、设超时（建议 2 分钟）， 的结构化 plist 结果识别**实际卷挂载点及设备**，不依赖 DMG 名称猜路径、不解析命令输出的自然语言；没有任何挂载点、不支持的、加密（需密码）或带许可协议（SLA）提示的映像明确失败，不自动输入密码或同意协议；超时后的残留挂载按第 5 条处理。plist 用标准库 `encoding/xml` 解析 XML plist（`internal/finder` 只有二进制 plist 读取），不新增依赖。读取 `hdiutil info -plist` 或等效官方信息识别已有挂载与其设备，不能把名称相同的不同映像视为同一文件：两边都 `filepath.EvalSymlinks` 后比较，必要时再比 `os.SameFile`。耗时操作在 `a.async`，主线程经 `a.post` 更新。
5. 挂载生命周期（审查后收窄，见 Review-1）：
   - **浏览挂载不自动卸载**，与 Finder 双击 DMG 的行为一致：卷留在 `/Volumes`，侧边栏「位置」照常显示并可用现有推出按钮（`sys.Eject`）推出；程序退出也不卸载。不做「离开所有窗格后卸载」的引用计数（历史、工作区、文件监听、预览缓存都会持有路径，难以可靠判断，且监听未停时 detach 必然失败）。
   - **右键安装的临时挂载**：仅当 `hdiutil info` 显示该映像在发起前未挂载、且本次 attach 成功时，记录其整盘设备（plist 中的 `/dev/diskN`）为本应用所有；复制结束（成功、失败或取消选择）后在后台对该设备执行一次普通 `hdiutil detach`，不加 `-force`。失败只在状态栏提示卷位置，由用户手动推出。
   - 已挂载（含用户或本应用先前浏览挂载的）映像一律复用且不卸载。同一映像在安装进行中再次触发安装时直接忽略（沿用 `installing` 以 DMG 路径为键）；进行中被「打开」浏览时，所有权转为浏览挂载，安装结束后不再卸载。所有权表只在主线程读写。
6. 提示复制的状态和失败细节沿用现有安装结果；有多个卷或重复 app 名称时选择项需附卷名称/相对位置以可区分。禁止覆盖目标、禁止把 `/Applications/goFinder.app` 通过本机测试复制覆盖。安装源在挂载失效或外部卸载后失败时真实报告，不尝试清理其他卷。

## 涉及文件（预计）

- `gui/app.go`、`gui/appinstall.go`、`gui/view.go`、`gui/sys.go`：打开与右键入口、系统接口、后台请求与状态更新。
- 新增 `internal/dmg`：DMG 识别、plist 解码、卷/设备与归属、根目录应用列表、可注入命令执行器；避免 MyGo 依赖，优先复用已有 plist 能力，不能引入新第三方库。
- 按实际改动扩展 `gui/*_test.go`、`internal/dmg/*_test.go`，并更新 `docs/plan.md`（`### 阶段 18 后修订二十一`，以实施时下一个编号为准）、本 PRD 实施记录及设计规范（如界面涉及新 token 才更新）。

## 可验证验收标准

- 打开本地有效 DMG 后仍在 goFinder 中浏览其真实挂载点；当前列、父列及子列、键盘及鼠标入口作用于正确项目；切换目录/窗格后的过期挂载结果不劫持用户位置。
- 根目录一个有效 app 时，DMG 两个右键选项分别以保留隔离和解除隔离模式调用既有安装器；多个 app 可选择且取消无安装；无 app、格式无效、只含符号链接、密码/损坏/不可读、卸载失败时有清楚结果且不误报成功。
- 已挂载 DMG 内的 app 仍显示既有三项打开菜单与两项右键安装；ZIP、普通文件、已安装应用和本机 goFinder 更新行为不回归。
- 浏览挂载在离开、切换窗格、关闭窗口后均保持挂载；右键安装的临时挂载在复制成功/失败/取消选择后各只 detach 一次且只对记录的设备，不加 `-force`；发起前已挂载的映像从不 detach。路径有中文、空格、引号、前导 `-` 时不发生 shell 注入。
- 不在 UI 主线程执行磁盘镜像或复制；相同镜像的重复触发不造成重复任务、错误卸载或错误导航；hdiutil 超时或需要密码/同意协议时报告失败且界面不卡住；挂载、扫描、复制、卸载任一失败均反馈正确阶段。

## 测试计划

- 单元测试使用伪命令执行器和 plist 夹具（以真实 `hdiutil attach/info -plist` 输出为样本，去除个人路径）覆盖多分区、零/多应用、现有挂载复用、路径转义、错误、资源引用及 detach 所有权；临时目录模拟 app 和目标，不碰用户真实 `/Applications`。
- UI Tester 使用 `fakeSys` 覆盖双击/打开键、三列右键目标、多应用选择与取消、两种安装模式、失效请求及后台结果；验证不修改用户既有快捷键及正常应用打开。
- 使用临时目录内自主生成的最小只读 DMG 验证真实 `hdiutil` plist、挂载、根目录发现和卸载；只对测试创建的设备执行 detach，绝不修改系统默认设置或覆盖安装用户应用。记录未测试的加密及实际 Intel 机器限制。
- 执行 `gofmt -l gui internal`、`go vet ./...`、`go tool mygo vet .`、`go tool mygo vet ./gui`、`go test ./...`；共享状态运行 race 测试；新界面生成并检查浅色/深色截图；按项目约定 `Apple_self_dev` 签名双架构 build（不安装、不 `-upload`）。

## 风险与回滚

- DMG 挂载是系统资源，必须按所有权及引用关系跟踪；失败时仅保留可见的本次挂载并告知路径，不能强制卸载或删除他人数据。用户手动推出后进行中的复制可能失败，应报告失败且不修改源。
- 用户态测试真实 DMG 时，只挂载测试自建映像；`hdiutil detach` 的参数必须是该次 attach 返回的设备，不能用卷名或 `/Volumes/<名称>` 拼接。
- 已有安装器的 `Lstat` 后重命名存在先前审查接受的小概率竞争，维持现有行为，不扩大覆盖能力。镜像不可信，绝不自动执行其中代码；解除隔离只对用户主动选择的副本按既有功能处理。
- 任一关键验收失败或无法安全判断卷归属则暂停、标记 `needs-human`；回滚通过普通 revert 相关合并提交，不改写主线、不永久删除用户数据。发布损坏时遵守现有更新签名和双架构分发恢复流程。
